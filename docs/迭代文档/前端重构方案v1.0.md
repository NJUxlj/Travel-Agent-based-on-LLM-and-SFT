> **产品定位**：旅游路线规划多智能体系统的 Web 客户端
> **技术栈**：TypeScript · React 19 · Ant Design 5 · Vite
> **日期**：2026-04-16
> **版本**：v1.0

## 一、旧前端现状与问题

### 1.1 现有 `src/ui/` 文件总结

| 文件 | 功能 | 问题 |
|------|------|------|
| `app.py` | Gradio 双 Tab（对话 + 思维导图），调用 `TravelAgent.generate_response` | Gradio 无法定制 UI；import 时 mindmap.py 触发 Gradio 副作用 |
| `mindmap.py` | `MindMapGenerator`（HF 本地模型 + Graphviz 渲染 PNG）+ 独立 Gradio Blocks | 功能有价值（LLM→层级文本→Graphviz 图），但与后端强耦合 |
| `rag_web_demo.py` | RAG 演示界面（对话 + 工具 JSON + Chroma 匹配 + 训练监控占位） | 功能未闭环，训练监控为假数据 |
| `webui_demo.py` | Gradio 最小示例（`greet` + `image-classification`） | 与旅行产品无关，纯测试文件 |

### 1.2 核心结论

- 旧前端全部为 Gradio Python 代码，**无法满足**定制化 UI/UX 需求
- **思维导图功能**有用户价值，但不应作为独立 HTTP 接口暴露，而应**注册为 Agent 工具**，由 Agent 自主判断是否调用，抽取回复文本为思维导图后内联显示在对话页面
- 旧 `src/ui/` 目录在重构后**全部废弃删除**

## 二、新前端技术选型

| 类别 | 选型 | 版本 | 理由 |
|------|------|------|------|
| 语言 | TypeScript | 5.7+ | 类型安全、IDE 支持 |
| 框架 | React | 19 | 生态成熟、并发模式 |
| UI 库 | Ant Design | 5.x | 企业级组件、中文友好、开箱即用 |
| 构建 | Vite | 6.x | 极速 HMR、ESM 原生 |
| 路由 | React Router | 7.x | 声明式路由 |

| 图表 | @ant-design/charts | - | 训练监控曲线 |
| 代码规范 | ESLint + Prettier | - | 统一风格 |

### 4.3 思维导图（对话页面内联展示）

思维导图**不再作为独立页面**，而是作为 Agent 工具调用结果**内联显示在对话气泡中**。

**触发机制**：
- 后端将 `generate_mindmap` 注册为 Agent 工具
- Agent 在生成旅行规划等结构化回复后，**自主判断**是否调用该工具将回复文本抽取为思维导图
- 工具返回的思维导图 JSON 数据随对话响应的 `tool_calls` 一起返回前端
- 前端检测到 `generate_mindmap` 工具调用结果后，在回复气泡下方渲染 `MindMapBubble` 组件

```python
# 后端：注册为 Agent 工具，而非暴露为 HTTP 端点
def generate_mindmap(text: str) -> dict:
    """
    将一段旅行规划文本抽取为结构化思维导图。
    当你生成了详细的旅行行程规划后，调用此工具将规划内容
    转换为思维导图，帮助用户更直观地理解行程结构。

    Args:
        text: 需要转换为思维导图的旅行规划文本

    Returns:
        思维导图的树形结构 JSON
    """
    # MindMapGenerator 内部用 LLM 将文本解析为层级结构
    generator = MindMapGenerator()
    return generator.generate(text)

# Agent 工具注册（以 AgentScope 为例）
toolkit.register_tool_function(generate_mindmap)
```

**前端渲染**：
- 使用 `@ant-design/graphs` 中的 `MindMap` 组件（基于 G6 图可视化引擎）
- 默认折叠，用户点击展开后显示完整思维导图
- 支持缩放、拖拽
- 支持导出 PNG/PDF（html2canvas + jsPDF）

## 五、核心技术方案

### 5.1 流式对话（SSE）

```typescript
// hooks/useSSE.ts
export function useSSE(url: string) {
  const [messages, setMessages] = useState<SSEEvent[]>([]);
  const [isStreaming, setIsStreaming] = useState(false);

  const startStream = useCallback(async (body: object) => {
    setIsStreaming(true);
    const response = await fetch(url, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(body),
    });

    const reader = response.body!.getReader();
    const decoder = new TextDecoder();

    while (true) {
      const { done, value } = await reader.read();
      if (done) break;

      const chunk = decoder.decode(value);
      const events = parseSSEEvents(chunk);
      setMessages(prev => [...prev, ...events]);
    }

    setIsStreaming(false);
  }, [url]);

  return { messages, isStreaming, startStream };
}
```

### 5.4 训练监控实时更新

```typescript
// hooks/usePolling.ts
export function usePolling<T>(
  fetcher: () => Promise<T>,
  interval: number = 5000,
  enabled: boolean = true,
) {
  const [data, setData] = useState<T | null>(null);

  useEffect(() => {
    if (!enabled) return;
    const timer = setInterval(async () => {
      const result = await fetcher();
      setData(result);
    }, interval);
    return () => clearInterval(timer);
  }, [fetcher, interval, enabled]);

  return data;
}

// 在 TrainingPage 中使用
const jobDetail = usePolling(
  () => api.training.getJob(jobId),
  3000,
  job?.status === 'running',
);
```
